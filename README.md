# geared_motors 项目说明

本文根据仓库中的固件源码、CubeMX 配置和工程文件整理。仓库未提供独立的产品说明书；PCB 二进制设计文件及机械模型仅作目录登记，未解析其内部设计。

## 项目概述

本项目使用 STM32F103 系列单片机控制减速电机方向，采集编码器数据，并通过 OLED 显示计数与换算结果。USB CDC 接口用于接收二次函数参数，参数通过 AT24C16 EEPROM 保存。

当前代码实现方向控制、编码器计数和距离换算，未见 PWM 调速或速度闭环控制逻辑。距离的物理单位及编码器每转脉冲数尚需结合实际机构标定。

## 硬件接口

下表依据固件定义整理，实际接线应与原理图及实物核对。

| 信号 | 引脚 | 固件用途 |
| --- | --- | --- |
| OA | PB13 | 电机方向输出 A |
| OB | PB14 | 电机方向输出 B |
| EN12V | PB15 | 逻辑任务启动时置高 |
| DOWN | PB8 | 低电平有效的按键输入 |
| UP | PB9 | 低电平有效的按键输入 |
| TIM2_CH1 | PA0 | 编码器通道 1 |
| TIM2_CH2 | PA1 | 编码器通道 2 |
| I2C1_SCL | PB6 | OLED 与 EEPROM 总线时钟 |
| I2C1_SDA | PB7 | OLED 与 EEPROM 总线数据 |

CubeMX 配置的系统时钟为 72 MHz，I2C1 速率为 100 kHz。OLED 地址宏为 `0x78`，属于传给 HAL 的移位后地址。AT24C16 的基础 7 位地址为 `0x50`，容量为 2048 字节，页大小为 16 字节。

## 启动流程与任务

主程序依次初始化 HAL、系统时钟、GPIO、DMA、TIM2 和 I2C1，启动 TIM2 编码器及更新中断，然后创建 FreeRTOS 任务并启动调度器。

| 任务 | 优先级 | 主要行为 |
| --- | --- | --- |
| LOGI | Normal | 初始化 USB，置高 EN12V，每轮延时 1 ms 后读取按键并控制 OA/OB |
| OLED_DISPLAY | Idle | 初始化显示与参数，约每 200 ms 更新显示；公式变化时发送文本并保存参数 |
| USB_CDC | Idle | 每轮延时 1000 ms，当前周期发送代码已注释 |

按键对应输出如下，实际旋转方向由接线决定。

| UP | DOWN | OA | OB | 行为 |
| --- | --- | --- | --- | --- |
| 按下 | 松开 | 高 | 低 | 方向一 |
| 松开 | 按下 | 低 | 高 | 方向二 |
| 松开 | 松开 | 低 | 低 | 停止驱动输出 |
| 按下 | 按下 | 低 | 低 | 停止驱动输出并清零编码器 |

## 编码器与距离换算

TIM2 使用 `TIM_ENCODERMODE_TI12`，预分频配置为 1，自动重装载值为 4200。更新中断根据计数方向增减 `Encoder_Overflow`。

当前实现使用以下计算：

```text
x = TIM2.CNT / 4200 + Encoder_Overflow
y = a × x² + b × x + c
```

`get_Encoder()` 仅返回累计溢出量；OLED 的 `Rounds` 字段显示该值，并非包含当前计数小数部分的完整转数。OLED 还显示 `Encoder`、公式文本和 `Distance`。

## USB 参数设置

USB CDC 接收回调将数据交给 `send_usb_to_data()`，再调用 `set_Equation()` 解析。当前格式为：

```text
y=0.2xx+1.2x+2.1
```

解析格式串为 `y=%fxx+%fx+%f`。其中 `xx` 表示平方项，建议使用与示例一致的小写格式。解析成功后更新系数和变化标志，由 OLED 任务检测变化、回传公式文本并调用 `Formula_Save()` 保存。当前未实现明确的成功/失败应答协议，也未实现跨 USB 数据包的命令拼接。

EEPROM 参数从 `0x000` 开始，包含有效标志 `0x4B4F4B49` 和三个 float 系数，共 16 字节。启动加载失败时使用默认值 `a=0.2`、`b=1.2`、`c=2.1`。

## 开发与构建

可通过 `MDK-ARM/code.uvprojx` 或 `EWARM/code.ewp` 打开已有工程。修改外设配置可使用 `code.ioc`，重新生成代码前应保留用户代码和自定义驱动。

CMake 配置要求 CMake 3.25 及以上，并使用 `arm-none-eabi` 工具链，目标产物为 `code.elf`、`code.hex` 和 `code.bin`。当前 CMake 文件存在以下需要核对的问题，因此本文不将其视为已验证可用的构建入口：

- 编译和链接参数写为 `-mcpu=cortex-m1`，与 STM32F103 使用的 Cortex-M3 内核不一致。
- 同时定义 `STM32F103x8` 与 `STM32F103xB`，应依据目标芯片统一。
- 包含目录未列出 `APP/`，但部分源码直接包含其中的头文件。
- 源码收集规则未包含 `MDK-ARM/` 或 `EWARM/` 下的启动汇编，应核对启动文件是否实际参与构建。

## 当前实现需关注的问题

- USB 接收复制后未显式补字符串结束符，后续却使用 `sscanf()` 按字符串解析，需完善长度和结束符处理。
- OLED 任务使用 `char str[15]` 配合多处 `sprintf()`，公式文本可能超出缓冲区。
- 公式显示格式为 `Y=...X+...x+...`，未明确显示平方符号，与实际二次函数计算存在表达差异。
- 同时按键分支中的等待条件在刚进入该分支时即为假，不能实现等待按键松开的效果。
- 自动重装载值为 4200，计数周期与换算分母的关系需核对，并结合实际编码器校准。
- USB 回调与任务共享公式参数，OLED 和 EEPROM 共用 I2C，总线及参数访问的并发行为需进一步检查。
